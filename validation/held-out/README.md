# `validation/held-out/`: the engine against P6 on schedules it was never fitted to

The P6 comparison matrix in [`../p6-comparison/`](../p6-comparison/) is fitted: the engine was corrected against the capture it passes. The sets here are held out. Each is generated from a public randomness-beacon round named before it was published, frozen, scheduled by Primavera P6, and scored against the engine once. The score is published as it comes out.

The rules are in [`PROTOCOL.md`](PROTOCOL.md).

| File | What it does |
|---|---|
| `generate_held_out.py` | Writes a set of synthetic P6 XER schedules from a seed (standard library only). `--dates pre2020` (H6) dates them before 2020; the default is the window H1 to H5 used. `--features wide` (H8) adds resource dependent work, level of effort, WBS summary, suspended work and external dates; `--features wide2` (H10) draws them heavier and puts about half the cases under progress override; `--features wide3` (H21) adds open ends hung off the network and "Make open-ended activities critical"; `--features wide4` (H22) adds expected finishes on work not yet started and on As Late As Possible work, and the edges of the open-ended rule; `--features wide5` (H23) adds a Mandatory Finish under an expected finish whose successor needs the work earlier, mandatory dates on resource dependent work, milestones with an expected finish, and a mandatory date beside a second constraint; `--features wide6` (H24) adds "Calculate multiple float paths" in about half the cases, mandatory dates in the second slot on both sides, a Mandatory Start against finish-to-finish and start-to-finish predecessors and against external dates, an expected finish passed by its requirement, As Late As Possible and expected finishes on resource dependent work whose resource keeps other days or hours, and assignments with no work left and a lag; `--features wide7` (H25) adds, on new activities not yet started, resource dependent work placed back from a finish-to-finish or start-to-finish requirement onto hours only its resource works, an assignment with no work whose lag lands off the activity calendar under a start-to-start bound at a close, an expected finish on resource dependent work whose resources work Mon-Thu on a calendar that works Saturday (a Mandatory Start on a Friday on about half), and assignments with no units, written so or left so by P6's import, with no duration under a start-to-start bound and beside work on a resource that works fewer days; `--features wide8` (H26) adds, after wide7's draws and only where they drew, an assignment with no work and a lag under a start-to-start bound at a Friday close, beside work whose finish-to-start successor holds the late finish where the work under the bound ends or later, and As Late As Possible work beside an assignment with no duration, its slide's bound at the next opening after its early finish or a day later; `--features wide9` (H27) draws what wide8 draws, except that no activity gets two assignments of one resource (H26-08 A1490 drew one; P6's import keeps one assignment per resource on an activity). |
| `freeze.py` | Fetches the named drand round, generates the set from it, and records every hash in `manifest.json`. |
| `readback_p6_sqlite.py` | Reads P6's own schedule of each case back from a P6 Professional SQLite database, read-only. |
| `import_p6_sqlite.py` | From H8: after each case's import and before its F9, records what P6's import made of the case (read-only), including its sizing of resource dependent work. |
| `p6_imported_overlay.js` | From H8: lays P6's sizing of resource dependent work over a case file before the engine reads it. After H26: where P6's import kept one assignment of a resource the case file gives an activity twice, it drops the others, as the import did. |
| `merge_cases.py` | From H9: writes the frozen cases as one XER, so P6 imports the whole set at once. |
| `model_p6_import.js` | From H26: a model of how P6's import sizes resource dependent work, written from the imports recorded so far, which it reproduces (H8 to H25: 1,025 activities and 1,393 assignments; 59 P6 probe sets: 687 activities and 855 assignments). Not part of any score. It checks, before any P6 time, that a generator profile's shapes reach their rules once P6's import has sized them; its prediction for each new set is measured against P6's record after the capture. |
| `score_held_out.js` | Runs `cpm-engine.js` on each frozen case through its public API and compares it with P6, field by field. |
| `score_whole_day.js` | From H6: compares the engine's whole-day pass with the calendar day of P6's dates (`--engine <file>` runs a diagnosis of another engine, never a score). |
